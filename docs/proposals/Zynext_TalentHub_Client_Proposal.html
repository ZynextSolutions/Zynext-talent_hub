01 · Executive summary

An operating system for corporate learning — assign, examine, certify, prove.

Built for enterprises, academies, and regulated teams. The client receives a complete web application: a Next.js learner and admin experience, an Express API, and PostgreSQL with tenant isolation on every organization-owned record.

What you get on day one

  • Learner home, catalog, and a full learn player
  • Course Studio with modules, live sessions, SCORM 1.2, and assessments
  • Org-tree assignment to organization, division, department, team, or person
  • Question banks, grading queue, and certificate designer
  • Analytics hub, seven operational reports, compliance ZIP
  • Platform console for Super Admins operating many tenants

Five reasons this is not a classroom LMS

  1. Org-aware. Assign once to a department; enrollments follow the tree. Managers see only their subtree.
  2. Studio, not a file dump. Eight lesson types, completion rules, skills, publish history.
  3. Assessments that gate proof. Pre, final, survey, module quiz — finals can block the certificate.
  4. Certificates you can show an auditor. Unique numbers, branded templates, public verify.
  5. Reporting in-product. Eleven analytics tabs, CSV / PDF / XLSX, scheduled reports, BI API keys.

Presented throughout as Zynext TalentHub — one commercial name on login, admin, learner, and platform surfaces.

05 · Feature catalog

Shipped in the running product — not a wishlist.

Authentication & security

Slug + email login so the same person can exist in two tenants. 15-minute access tokens, 7-day rotating refresh, MFA (TOTP), OIDC SSO, lockout after 10 failures, password 12–128 with a blocklist. Helmet, CORS allow-list, HSTS in production.

Multi-tenant org model

Shared PostgreSQL with organization_id isolation. Drag-and-drop tree: Division → Department → Team. Move-reconcile when people change seats. Settings: timezone, self-enroll, answer reveal, certificate prefix (default COR), USD or MMK.

Course Studio

Tabs: Outline, About, History, SCORM, Assessments, Sessions, Assignments, Skills. Status DRAFT → PUBLISHED → ARCHIVED. Completion: all lessons, required, or percentage. Prerequisites, availability windows, duplicate, revision snapshots.

Eight lesson types

Video, reading, document, knowledge check, discussion, instructor-led, virtual ILT, SCORM 1.2. Caps: thumbnail 1 MB, documents 25 MB, video 80 MB, SCORM 100 MB. Media only via authenticated API — raw /uploads is forbidden.

Enrollments & progress

Five assignment targets. Due dates, recertify-every-N-days, reminders. Statuses: enrolled, in progress, completed, revoked. Sources include path and recertify. Lesson watch position and completion.

Assessments & banks

PRE, FINAL, SURVEY, MODULE_QUIZ. Seven types: MCQ, true/false, multi-select, short answer, fill-blank, matching, essay. Bank draw by count and tags. Timed attempts. Default pass 70%, max 3 attempts (surveys unlimited).

Grading queue

Objective items auto-score. Short answer and essay go to /grading. Score plus feedback. Statuses: auto-graded, pending review, graded, expired.

Certificates

Auto-issue at 100% progress and a passing final if one exists. Themes midnight, ivory, slate. Logo, signature, background. Public verify and PNG download. Path certificates use PREFIX-PATH.

Analytics & reports

Eleven tabs including compliance, ROI, skills, and xAPI. Seven reports with CSV, PDF, XLSX. Schedules daily / weekly / monthly. API keys scoped to reports:read for BI pull.

Learning paths & skills

Ordered courses with unlock notifications and a path certificate. Skill catalog mapped to courses and system roles, levels 1–5. This is a light competency graph, not a full talent suite.

Community & notify

Eight notification kinds, org/course announcements, org and course forums. Webhooks today: enrollment.completed and report.delivered.

Platform jobs

Five HTTP jobs behind a job secret: reminders, recertify, scheduled reports, cert-expiry, analytics snapshots. Production must schedule them (cron or Kubernetes). There is no in-app worker.

Do not claim AI. There is no generative authoring, auto-question generation, chatbot tutor, or LLM grading. Course Studio is human-authored. SCORM is 1.2 only — not 2004.

07 · System workflows

Fifteen journeys, from invite to verified certificate.

Each workflow is how the running system actually behaves — including the exception paths a buyer’s IT team will ask about.

1. Register a new organization

Actor: prospective Org Admin · Trigger: /register

2ValidateUnique slug, password policy

4SessionORG_ADMIN tokens → /dashboard

Exceptions: slug taken, weak password, rate limit 5 / 15 min. Enterprise clients typically disable public registration and let Super Admin create the tenant instead.

2. Login and session

Actor: org user · Trigger: /login with slug + email + password

2Lockout10 failures block the account

Refresh rotates the token family; reuse of an old refresh revokes the family. INVITED users cannot sign in until they accept. Suspended org or user is rejected.

09 · Security, compliance, trust

Tenant isolation you can explain in a security review.

Identity

Passwords hashed with bcrypt (production cost 12+). Short-lived access tokens, rotating refresh. Optional authenticator MFA. Optional company OIDC.

Authorization

43 named permissions. Managers confined to their department. Instructors write only courses they created. Employees stay on self.

Isolation

Every learner, course, and certificate belongs to one organization. Org users cannot switch tenant via query parameters. Platform access is explicit and audited.

Uploads

Files are not world-readable. Direct /uploads is blocked. Playback goes through an authenticated media service.

Audit & proof

Mutating actions log actor, action, resource, request id, IP. Certificates are uniquely numbered and publicly verifiable (30 lookups / minute).

Honest boundary

We do not claim SOC 2, ISO 27001, GDPR DPA, or HIPAA — none are evidenced in the product. Email, Redis-backed limits, and object storage are go-live decisions.

Designed limits

  • Pagination default 25, max 100; catalog 24 per page
  • Enrollment cascade in chunks of 500
  • JSON body 1 MB; large media on dedicated routes
  • If cron is down, reminders and recertify do not run
  • No published concurrency or CDN numbers — treat scale as a pilot proof point

11 · Engagement model

Discovery → pilot → production. Do not skip the mail and jobs.

0

Discovery

1–2 weeks. Brand, register on/off, SSO vs MFA, org tree, mandatory courses, hosting, KPIs.

1

Pilot

4–6 weeks. 50–200 learners, 3–5 courses, one path, branded certificate, weekly overdue review.

2

Production

6–10 weeks. CSV/SSO, cron, SMTP, backups, disable public register, compliance ZIP rehearsal, optional BI key.

3

Harden

Redis for limits/idempotency, object storage, horizontal API, load-test video and SCORM.

Out of the box

Four org roles + Super Admin, certificate designer, USD/MMK, OIDC, local uploads, HTTP jobs, reports in three formats.

Typical statement of work

Custom roles, SAML/SCIM, S3/Azure Blob, white-label, extra webhooks, native apps, SCORM 2004, any AI feature. Do not sell these as standard until they are in a SOW.
